# LOM AI - учебный mock-клиент

LOM AI - образовательная платформа с ИИ-инструментами для школьников и преподавателей. Здесь представлен веб-клиент чата с локальным mock AI-agent для тестового задания.

## Демо

[Посмотреть демо](https://neuro-test-xv2h.vercel.app)

## Запуск

```sh
npm install
npm run dev
```

## Стек

- Vue 3;
- TypeScript;
- Vite;
- Pinia;
- `localStorage` для локального хранения диалогов.

## Структура

```text
src/
├── agent/mockAgent.ts       # сценарии агента и поток событий
├── composables/
│   └── useChatAgent.ts       # запуск агента и обработка его событий
├── components/
│   ├── ChatAside.vue         # список диалогов и создание чата
│   ├── ChatEmpty.vue         # пустое состояние и быстрые prompts
│   ├── ChatMain.vue          # сообщения, статусы и retry
│   └── icons/AppIcon.vue     # локальные SVG-иконки
├── stores/chats.ts           # состояние чатов и сообщений
└── App.vue                   # сборка экрана и UI-события
```

## Состояние чатов

Каждый чат хранит собственный массив сообщений. Сообщение содержит роль, текст, статус генерации и, при необходимости, состояние инструмента:

```text
Chat
├── id
├── title
└── messages[]
    ├── role: user | assistant
    ├── content
    ├── stage
    ├── status
    └── tool?
```

Изменения сохраняются в `localStorage` с deep-watch. При загрузке старые или неполные записи нормализуются, чтобы приложение не падало из-за устаревшей структуры данных.

## Mock-agent и streaming

`runMockAgent` — асинхронный генератор событий:

```text
started
status
tool_call
tool_result
text_delta
completed
error
```

Приложение создаёт пустое сообщение ассистента, затем постепенно дописывает его при каждом `text_delta`. Агент поддерживает:

- объяснение второго закона Ньютона;
- упрощение объяснения с учётом истории диалога;
- объяснение закона Ома;
- mock-калькулятор для простых выражений;
- искусственную ошибку по запросу со словом «ошибка»;
- медленную генерацию по запросу со словом «медленно»;
- остановку генерации через `AbortController`.

Связь агента с Pinia вынесена в composable `useChatAgent`. Он отвечает за запуск генерации, обработку по событиям, обновление сообщения ассистента, повтор запроса и остановку. Для каждого чата используется отдельный `AbortController`, поэтому несколько диалогов могут генерироваться параллельно.

## UX-состояния

Реализованы:

- пустой экран с быстрыми подсказками;
- создание и переключение диалогов;
- loading/status-сообщения агента;

## Использование AI-инструментов

Я использовал Codex для дизайна пустой страницы, ревью архитектуры, проверки краевых случаев и обсуждения UX-состояний. При разработке пришлось самостоятельно изменить предложенные решения:

1. Codex предложил хранить текущий ответ агента в отдельном объекте assistantAnswer. Я отказался от этого подхода и перенёс ответ в массив сообщений Pinia, потому что отдельный объект не был связан с интерфейсом реактивно. Для streaming сделал обновление существующего сообщения через updateMessage и appendToMessage.
2. В первой версии история чата сохранялась вместе со статусом генерации. Я заметил противорчие, что после перезагрузки статус «генерируется» восстановился, а запрос и AbortController нет. Диалог блокировался и stop не работал. Я изменил правило восстановления, незавершённый ответ становится остановленным, a уже полученный текст сохраняется, поэтому пользователь может продолжить работу.

## Ограничения

- mock-agent работает только по локальным сценариям;
- нет настоящей LLM и backend-синхронизации;
- данные хранятся только в браузере;
- математический инструмент поддерживает ограниченный набор простых выражений.
